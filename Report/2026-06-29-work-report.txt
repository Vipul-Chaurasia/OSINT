5. DORK TASK -> CONTENT SCRAPER INTEGRATION (Today's Final Item)

   - Problem: Large dork result files (e.g. 257 URLs) made manual URL copy
     impractical.
   - Solution: Pass dork task_id directly to content scraper.

   New file: content_scraper/dork_loader.py
     - Reads dorking_master/Results/results_{dork_task_id}.json
     - Resolves URLs from urls_sorted -> urls_grouped -> target_urls (deduped)
     - Optional target_type filter (e.g. "video", "profile")

   API example:
     curl -X POST http://localhost:8001/api/scrape-content \
       -H "Content-Type: application/json" \
       -d '{"dork_task_id": "e77dc530-4b7f-4f2b-8181-5c38c733c9be",
            "target_type": "video"}'

   - urls is now optional; either urls or dork_task_id (or both, merged)
     required.
   - Output JSON stores dork_task_id + dork_source metadata.
   - SQLite tasks table extended with dork_task_id column.
   - Env var: DORK_RESULTS_DIR (default: ../dorking_master/Results).
   - Tests: content_scraper/tests/test_dork_loader.py (6 tests, all passing).
